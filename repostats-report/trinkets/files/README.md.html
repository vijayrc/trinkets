1# trinkets
2
3A collection of small, self-contained developer utilities.
4
5Every tool here is deliberately stdlib-only at its core, so it runs from a clean
6checkout without a virtualenv, a lockfile, or a network round trip.
7
8| Utility | What it does |
9| --- | --- |
10| [`repostats`](#repostats) | Analyses a git repository and reports languages, build tooling, purpose, contributors, architecture flow, external dependencies, size metrics, and test coverage. |

42## repostats
43
44Points a static analyser at a git repository and answers eight questions about
45it. Nothing is uploaded anywhere; every check is local and read-only.
46
47### Usage
48
49```bash
50repostats # analyse the current directory
51repostats ~/code/myapp # analyse another repository
52repostats -f json -o report.json # machine-readable output
53repostats --max-commits 5000 # cap history scan on huge repos
54repostats --run-coverage # execute the repo's pytest suite (see warning)
55```
56
57Via the parent dispatcher:
58
59```bash
60trinkets repostats ~/code/myapp
61```
62
63### What it reports
64
651. **Programming languages** — file counts, code/comment/blank line splits and
66 percentage share per language. Config and markup (YAML, JSON, Markdown, …)
67 are tallied separately so they can't drown out actual source.
682. **Build tool and model** — detected build systems, package managers, PEP 517
69 backend, CI providers, containerisation, and whether the repo is a single
70 project, a multi-project layout, or a declared monorepo with workspaces.
713. **Purpose and overall logic** — inferred from README, package metadata,
72 detected frameworks, entry points and recurring path vocabulary.
734. **Contributors and timeframe** — commits, distinct authors, active span,
74 per-year histogram, insertion/deletion churn, and a bus-factor estimate.
755. **Flow diagram** — a Mermaid `flowchart LR` from caller through entry point,
76 controllers, services and repositories to datastores, caches and queues.
776. **External dependencies** — databases, caches, message brokers, search,
78 cloud, observability and auth systems, resolved from three independent
79 sources: package manifests, container images, and import statements.
807. **Size and structure** — LOC breakdown, class/type and function counts, HTTP
81 endpoint inventory, comment ratio and the largest source files.
828. **Testing and coverage** — frameworks, runners, test-to-source ratio, test
83 case counts, and line coverage read from any existing coverage report.
84
85Output is Markdown by default (drop it straight into a PR or a wiki) or JSON for
86piping into other tools.
87

124## Design notes
125
126### Measured vs. inferred
127
128The report separates what was **counted** from what was **guessed**, and labels
129every inferred section with a confidence level. Sections 1, 4, 6 and 7 are
130largely measurement. Sections 3 and 5 are inference, and say so in their
131headings. Each inferred node carries an evidence block naming the files that
132produced it, so a wrong conclusion is traceable rather than mysterious.
133
134If there isn't enough signal to draw a flow, the tool says that instead of
135inventing an architecture:
136
137> Not enough structural signal to infer a meaningful flow. The repository has no
138> recognisable layer directories, HTTP routes, or datastore dependencies — it is
139> most likely a library or a flat script collection.
140
141### Coverage is read, not run
142
143`repostats` does **not** execute the analysed repository's test suite by
144default. Doing so means running arbitrary third-party code, which is not a
145reasonable thing for an analysis tool to do silently. Instead it reads coverage
146from reports the repo already contains — Cobertura/JaCoCo XML, `coverage.json`,
147Istanbul summaries, or `lcov.info`.
148
149`--run-coverage` opts into executing `pytest --cov`. Only use it on code you
150trust.
151
152### One pass over the tree
153
154The walker reads each file exactly once and hands the decoded text to every
155probe, so an eight-part report costs a single traversal. File discovery prefers
156`git ls-files --cached --others --exclude-standard`, which honours `.gitignore`
157while still including uncommitted work in progress.
158
159Vendored directories, lockfiles, minified bundles, generated protobuf output and
160binaries are excluded from source counts.

164## Known limitations
165
166Worth reading before you trust a number.
167
168- **String literals can produce phantom endpoints.** Route detection strips
169 comments but not string literals, so a framework route written inside a test
170 fixture or a docstring is counted as a real endpoint. This repo triggers its
171 own bug: `tests/test_repostats.py` contains Flask routes as fixture strings,
172 so `repostats` reports trinkets as an "HTTP service / web API".
173- **Class and function counts are exact only for Python** (via `ast`). Every
174 other language uses declaration regexes — close, but it will miss unusual
175 formatting and can over-count. The report states which languages got which
176 treatment.
177- **The flow diagram is a layer sketch, not a call graph.** It is built from
178 directory and filename conventions. A codebase that doesn't name things
179 `service/`, `repository/` and so on will produce a thin diagram even if it is
180 well architected.
181- **Purpose inference is only as good as the README.** With no README and no
182 package description, it falls back to "a `<language>` project".
183- **Bus factor is a commit-count heuristic**, not a knowledge-distribution
184 measure. Someone with few commits may still be the only person who
185 understands a subsystem.
186- **Shallow clones** produce truncated history; the report warns when it detects
187 one.
188- Dependency classification covers a curated list in `knowledge.py`. Unknown
189 packages land in the `other` bucket rather than being guessed at.

193## Development
194
195```bash
196pip install -e ".[dev]"
197pytest # run the suite
198pytest --cov # with coverage
199ruff check src tests # lint
200```
201
202> **Status:** the test suite in `tests/` is written but has not yet been
203> executed in this environment — `pytest` was unavailable at the time of
204> writing. Treat a green run as unconfirmed until you have one.
205
206### Adding a utility
207
2081. Create `src/trinkets/<name>/` with a `cli.py` exposing `main(argv)`.
2092. Register it in `UTILITIES` in `src/trinkets/cli.py`.
2103. Add a `[project.scripts]` entry in `pyproject.toml` if it deserves its own
211 binary.
212
213Utilities are imported lazily, so a heavyweight or broken tool never slows down
214or breaks the others.
215
216### Layout
217
218```
219src/trinkets/
220├── cli.py # dispatcher across utilities
221└── repostats/
222 ├── analyzer.py # orchestrator: walk once, run every probe
223 ├── walker.py # file discovery + per-file line counting
224 ├── gitio.py # read-only git CLI wrapper
225 ├── languages.py # extension -> language, comment syntax
226 ├── knowledge.py # package/image -> infrastructure mapping
227 ├── models.py # report dataclasses
228 ├── probes/ # one module per report section
229 └── render/ # markdown and json output
230```
